# Parent directory-policy acquisition and cross-process accounting

Remaining parent policy acquisition must not discover policy outside the original
whole-job budget or release a cancelled thread/unknown descriptor. Native bot
permission and routing-home observation precede acquisition; neither policy rows
nor counters confer authority.

## Proposed finite binding

A retained policy-read owner opens only the lexical directory chain from / to
that observed home using directory/no-follow flags and held-parent-relative names.
It never opens profile.yaml, config, assets, chats or credential files. It checks
named/held identity, directory type, UID/GID and exact admissible modes. Prefixes
include / and total at most32. Root/home UID/GID match the nonroot service identity;
other UIDs are root or that service UID. One observed singleton mode is transferred
per prefix. Current native home and original authority are rechecked afterward.

Debit opens, metadata and path bytes before every effect under the same original
deadline and existing80/1024/32768 whole-job limits. Close owned descriptors once,
in reverse order. A close exception retains its exact owner/attempt record and
never implies empty debt or permission to retry a descriptor number. The parent
policy operation must settle/close before the same job launches its child, so
parent and child target-FD reservations do not silently overlap. Cancellation of
a caller/thread await is not native termination or descriptor settlement.

## Required private IPC evolution

Current schema2 has no charged-counter transfer. Do not use it for the new reader
and then silently give the child fresh credits. Introduce exact schema3 with
parent_work_counts containing the complete fixed counter key set, bounded exact
integers, permitted parent phase counters only and the original deadline/challenge.
No actual child fallback to schema2. Existing schema2 fixtures remain explicitly
inert legacy checks. Parent retains its authoritative snapshot; child initializes
its sole nonresetting ledger with those already-spent credits before processing.
No phase may reset or replace that ledger. Final result accounting must be checked
against the retained parent counters, source/operation and existing total limits;
a supplied counter map/hash is not proof the parent performed the work.

## Acceptance before routes

Independent review must fix the exact schema3 counter constraints, counter-import
API and parent/child result comparisons before implementation. Tests cover zero
filesystem effects before native authorization, secure default/named geometry,
symlink/rename/inode/mode changes, pre-effect exhaustion, expired original deadline,
partial acquisition and unknown closes, cancelled owned threads, extra/missing/
bool/negative/overflow counter fields, schema2 refusal by actual entry, full-budget
conservation and parent-target-FD settlement before child startup. Use synthetic
files only. Hard timeout/reaper/runtime provenance and native lifecycle gates stay
separate; no host route is authorized by this design.
