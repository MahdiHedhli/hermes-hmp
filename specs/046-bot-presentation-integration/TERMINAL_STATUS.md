# Terminal bodyless STATUS exchange — reviewed repair boundary

This is the next source implementation contract, not accepted implementation or
production admission. A native Darwin socketpair reproduces credential-API refusal
after peer close while buffered terminal bytes remain readable. The earlier actual
service FrameError's precise cause remains unproven.

## Retained connection identity

Authenticate the actual kernel peer before the exchange. Seal the successful
observation to the original native socket and descriptor identity, process context,
endpoint observation, fixed startup enrollment/generation and exact STATUS binding.
A failure of initial authentication cannot produce this state. No boolean switch,
generic cached-peer fallback, mutable enrollment or cross-connection reuse exists.

Once terminal STATUS transmission begins, after-await checks must retain current
local descriptor/context/endpoint/generation integrity. Credential API availability
cannot serve as a peer-liveness test after legitimate closure. This narrow state
cannot grant BEGIN/GO/RESULT, publication, work resumption or started release.

## Closed exchange and terminal lifetime

Only canonical bodyless STATUS/PENDING/UNKNOWN framing uses this terminal contract.
CLOSED retains its existing distinct ACK obligations and must not acquire implicit
ACK/release from EOF. Header/body bounds, exact operation/channel/boot correlation,
sequence, cancellation and the unchanged original deadline remain enforced.

Server retains the transport while waiting for gateway EOF under that same deadline;
already queued EOF is valid transport termination. Nonempty trailing data refuses.
A lost response or truncated frame remains ambiguous; it cannot renew a deadline,
reset a sequence, resend work, accept another peer or claim successful status.
EOF retires only known local transport ownership. Registry/native debt persists.

## Required causal checks before acceptance

- Successful initial authentication is mandatory; wrong peer/boot cannot enter.
- Legitimate gateway closure before the server post-send check and before EOF-wait
  entry must not require credential APIs that become unavailable after closure.
- A bounded buffered canonical reply after remote close remains tied to its original
  authenticated connection; arbitrary/truncated/trailing data cannot succeed.
- Replaced/stale descriptor, endpoint, process context, enrollment/generation or
  binding refuses; restoring fields cannot revive a poisoned owner.
- Original deadline/cancellation/reentry and independent local close proof survive
  every terminal transition, including partial acquisition and lost acknowledgement.
- PENDING/UNKNOWN never release registry/native debt. CLOSED ACK semantics remain.
- Existing BEGIN/GO/RESULT/data paths retain their current authentication boundaries.
- Independently review source and native causal coverage before any further owned-
  label fixture. A prior model pass does not qualify a new real-process run.

Full renderer, authenticated routes, native original authority and signed physical
character delivery remain separate open requirements. Host-local media has its own
authority contract and must never use a raw assistant path as permission to read.
