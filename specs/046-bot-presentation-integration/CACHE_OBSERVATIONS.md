Status: bounded source observations; not import, persistent absence or native admission.

The strict runtime path derives a typed cache source from the actual pre-IO
snapshot/context. Unique unresolved loose-cache paths are reserved together with
inherited artifacts and executable link hops under the original MAX_FILES limit.
No byte allowance or previous count is reset. Declared caches remain ordinary
original hash inputs, and expected tree absence/nonfile states rely on the actual
existing before/after exhaustive tree observations.

For loose absence, the SAME StartupArtifactOwner observes paths before and after
its existing file/link reads. Every directory open/close uses its original
retained descriptor records and context. Ancestors are walked descriptor-relative
with no-follow, original ownership/mode and identity checks. The cache leaf is
never opened or read. Only exact FileNotFoundError/ENOENT for the exact attempted
component is accepted, through a retained parent FD and validated error fields.
Permission, ENOTDIR, ELOOP, ambiguous outcomes, symlinks/unsafe ancestors and
present undeclared cache entries refuse. Unknown close acknowledgement remains
unknown; no retry or restored counter credit follows.

Both passes must identify the same missing component under the same ancestor
identities. Ancestor relationships are checked after the final negative stat.
Probe intent precedes effects; metadata probes leave the original byte-count
allocation unchanged. Sidecar sealing joins original phase/index/path/count and
closed descriptor allocations. Phase destination slots are rechecked AFTER the
last callback-bearing guard and immediately before assignment, preserving foreign
replacement state rather than overwriting it.

Strict runtime snapshots now retain eight fields: the original six snapshot
fields, loose-file ancestry and the original cache sidecar. File facts retain

These are sampled filesystem facts. A cache can appear later; current loader,
