# Native binding fixture migration — qualification repair

## November 10: original open-registration observations

The open-registration fixture now traces actual method frames and profiles the
original native open/close functions. It no longer replaces canonical `_open`
or `_native_walk_scope`. Supplied copied/missing registrations are injected into
the actual bound parameter; an independent marker outside exception handlers
requires confirmed writeback, distinct copy/missing None, exact owner failure,
unchanged byte/record/native-open observations and original ledger counts/attempts.

Post-open graft controls confirm a successful original walk and all three
original registration mirrors before replacing those mirrors. Cleanup requires
one original native close per claim/FD, immediate EBADF observation and the exact
literal close receipt with successful close state. Unknown/refused open records
remain unknown: their conservative `closed` diagnostic is intentionally false.
That diagnostic cannot replace original cleanup proof or renew output authority.
EBADF here is a point-in-time synthetic FD observation, not a general process
closure/no-reuse proof.

Six fault cases pass on both Python3.14.9 and3.11.15. The full current eight-case
run passes those six and fails both normal-completion controls at the original
60-second deadline. The normal `checked._ready` requirement remains intact.
This closes neither normal startup nor the broader baseline gate; no fresh
110-case aggregate result is inferred. Independent exact fixture review accepted
the tightened observations/assertions, not normal/runtime/device qualification.


The combined source1ab9910 baseline failed 215 cases and passed 1,065. Multiple
fixtures replaced canonical os.open/readlink aliases even for normal observation;
the new binding continuity check correctly refuses those replacements. The failed
baseline is preserved and does not qualify the integration.

Test-only observers now watch owned HMP helpers or exact native-function c_call
profile events. Native aliases and production checks remain unchanged. Synthetic
post-native/pre-ack fault timing uses a child-only trace on the exact owned helper
code/source boundary; it is not a production callback or verifier bypass.

A trace exception disables later trace events. Independent profiling therefore
retains all native close observations after the injected fault. Duplicate-close
checks use original descriptor-record identity, not numeric fd values, which can
be reused legitimately. Assertions retain exact original total, fd identity,
close-attempt flags, one unknown record and the actual injected fault. Native-open
attempt observations precede effects; successful helper returns are not used as
proof of zero attempts.
