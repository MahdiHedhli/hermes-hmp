This advances BR3/BR6 toward the full metadata/classic/blobatar/custom-image
feature. Independent review accepts the BEGIN/READY source boundary, including
monotonic channel adoption and post-peer deadline/cancellation checks. It is not
a substitute final feature or production activation. The
bounded no-GO service passed separately. Subsequent coupled selected-v2 GO source

remain required and incomplete.

## One shared admission and native authority ledger

Use the existing ParentAuthorityAdapter reservation and JobOwner credits; do not
create another queue, challenge source, capacity counter or native policy engine.
OriginalHeaders remain only in the gateway. INITIAL/BEFORE, joined parent policy
work and its fresh PRE_GO postcheck remain mandatory before transferring input3.
A broker binding, peer snapshot or frame is never phone authorization.

Add a separately retained RemoteOperationOwner and explicit remote custody field
on the existing native/job records. One shared exact RemoteSlot is captured at
reservation and installed monotonically once; both records view that same slot.
It is never record.child or a Popen stand-in. Reject any local process, supervisor,
child or prior remote adoption, and reciprocally reject local adoption afterward.
A ParentAuthorityAdapter factory retains the allocation before initialization;
the JobOwner holds the same exact object before any exchange effect. Failed
construction remains retained and UNKNOWN in both ledgers; no local no-child or
prelaunch shortcut may release it. Direct unretained construction cannot
be used to dispatch work. No partial owner attributes supply terminal evidence.

Local bind_child/go/feed_result/custody/refuse-prelaunch/retirement paths must
reject a remote-owned job. Local WAIT/GROUP_GONE/SIGNAL_CLOSED and the legacy
no-process closure shortcut cannot retire it. Cancellation retains the existing
credit and revokes output. This slice adds no remote terminal-release path.

## Input ownership, fixed scope and BEGIN/READY

its existing parent snapshot. Require the actual policy-thread join and completed
postcheck, not only decoded equality. The remote factory accepts only that transfer and
joins decoded challenge, epoch, iid, canonical profile, home/root, operation,
original deadline, policy and source context to the same native/job record. No
caller-provided bytes, alternate profile/home, late replacement or second transfer
may replace the original. The retained input is bounded by existing active-job
capacity and INPUT_LIMIT; it contains no original bearer/header/provider secret.

The owner seals its original ParentAuthorityAdapter/opaque operation/record,
JobOwner/handle, policy work and packet reference, exact BrokerBinding and
SocketChannel, authenticated enrolled peer/boot, loop/context and original
monotonic deadline. The binding iid must match the original native lease. A new
broker boot or restored stale field cannot resume a poisoned operation. The
SocketChannel is claimed monotonically once; ordinary I/O, another reservation
and terminal STATUS adoption cannot reuse it. Owner-authorized I/O permits only
one exact BEGIN0 packet and one READY receive after the write returns. Kernel
nonblocking and captured native Python timeout0.0 are checked before I/O. Startup
manifest/source context is not itself runtime attestation or a Hermes version
allowlist.

The first implemented exchange is one BEGIN intent and one canonical bodyless
READY under that original deadline. Record intent before any possibly partial
write; preserve ambiguity across cancellation or lost response. Recheck native
listener/store/device/profile/fence generations around every await. After peer authentication returns, recheck local FD/endpoint, full original scope,
phase, original deadline and pending task cancellation again. Poisoning uses the
reservation's original owner/handle/fence snapshot, not callbacks supplied by
drifted metadata. No retry,
reconnect BEGIN, fresh deadline, GO, output read, publication or inferred closure
is available from READY. Wire/control ownership stays reachable after failure.

## Source acceptance checks

- Existing local semantics and common waiting/metadata/avatar/profile/FD limits.
- Real parent snapshot/input3 construction under synthetic native observations;
  original headers stay in the parent and are absent from wire bytes.
- Wrong instance/profile/operation/challenge/deadline/packet/source and changed
  broker/channel/native generations refuse before dispatch or publication.
- Partial construction/write, lost READY, cancellation/deadline, duplicate adoption
  and replay remain retained UNKNOWN/DRAINING; restoration cannot revive them.
- Remote jobs cannot use local custody, prelaunch refusal or no-child retirement
  to release credits/headers. No fake child or fabricated local event is created.
- BEGIN/READY wire tests use only synthetic homes/frames. No live host, real user
  messages, permission change, GO, RESULT or service deployment is authorized here.
- Independent source/negative review precedes convergence. Production startup,
  Linux manager and signed physical qualification remain distinct gates.
