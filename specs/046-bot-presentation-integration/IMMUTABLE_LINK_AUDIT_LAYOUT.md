## Original custody

Capture the layout before the actual original entry is published. Retain its
literal identity in the engine packet and join that same packet/layout through
the actual EntryOrigin, NativeFileLineage and Scope blueprint. Both inline Scope
publication seals and parent-current validation must retain that same identity.
A resource, current module export, copied packet or late import cannot nominate
the expected layout. Self-consistent mirrors do not establish original custody.

Use recursively exact immutable tuples/frozensets with exact-string names and
counts, plus strong original object references. Never retain only numeric IDs:
original objects must stay alive. Read fields with original tuple primitives;
no replaceable layout property, constructor or delegated checker may interpret
the expected table during a mutable-state audit.

The bootstrap constructor must prehold original inputs, validate shapes and
bounds, rejoin inputs after helper/constructor returns, and publish only its
literal successful return. A lost or copied return is refused, not reconstructed
from a global or coherent current export. Adding a layout to a late engine
packet alone is insufficient.

## Every-call obligations

Only immutable row shapes, expected name sets, role partitions and access routes
may be precomputed. Each call still reads and validates:

- Original system/registry/module namespace identities and all current keys,
  sizes, exports and original value identities.
- Every original class base, member key and member identity, including properties.
- Every function's code, globals, default tuple identity, exact keyword-default
  dictionary and entries, closure allocation and cell contents.
- Fixed role, type, constructor and dispatch relationships and original aliases.
- Fresh native actor, owner, scope, resource, custody, byte, ledger and cleanup
  state at the existing observation boundaries.

No cached mutable witness, shallow receipt, permission result, reusable audit
grant or changed deadline is permitted. Pure expected DATA is not authority to
perform a native operation. Original current references must be retained through
identity comparison. Exact collection/type fences precede unpacking, hashing,
equality or lookup; malformed local packets must not dispatch foreign protocols.
These remain fresh non-atomic Python audits, not a claim of immunity to arbitrary
tracing or monitoring mutations.

## Required acceptance

Before replacing any existing validation, prove actual early layout custody and
both publication seals. Reject copied layouts, coherent copied packets, late
nomination, altered schema interpretation, foreign equality/hash/length hooks,
same-sized replacement values, duplicate/missing expected keys, changed code or
defaults, closure and class/property drift. Reordered equivalent exact-string
keys must retain the intended existing semantics.

Then compare the complete real traversal and refusal/cleanup behavior on current
and minimum Python, including actual metadata and link-byte C calls, typed
admission, raw retirement, all phase finishes, snapshots/rechecks, pending/active
state, revocation and uncertain outcomes. Keep all existing native fault and
broader startup/runtime/service tests. Measure the complete path; a faster local
loop or passing layout tests cannot qualify image serving or a device build.
