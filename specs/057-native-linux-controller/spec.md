Run the selected NS1–NS7 native service's complete matrix and mutation journeys,
not an abbreviated avatar smoke test. Preserve the exact native loader/factory,
canonical image rows, authorization, bytes/revisions, isolation, revocation and
restoration, natural602-second cooldown, original request deadlines and actual

No live home, credentials, provider generation, real message, permissions, modes,
models, jobs, physical phone operation, deployment or store action.

## Actors and authority

Root remains sole author; existing character_custody_review is independent reviewer.
The trusted operator owns the ordinary disposable Linux runner, Docker daemon,
public input trees and private fixture roots exclusively throughout. This is not

Setup is distinct from runtime. A reviewed preparer still must establish exact
CPython3.14.9, the77 binary-only hash-pinned dependencies (no source builds),
source materialization and image download, then record the complete interpreter
and environment inventory with expected manifest hash. The controller checks
that supplied trusted preparation record and before/after bytes; a self-authored
manifest alone is not provenance or proof the version claim is true. Runtime
inventory rejects outside symlink targets, special/hardlinked/writable-by-others
regular files/directories and changed bytes. Linux symlink0777 is not a write
grant: link ownership and in-tree resolved targets are checked, and the target
files/directories remain inventoried with normal mode checks. Source manifest and every13,201 source file are checked.

## One-shot container lifecycle

Use only the fixed Ubuntu amd64 leaf digest and local daemon socket. Runtime
create uses pull=never. Retain unique name/owner label and create intent before
one create; inspect the resulting full ID and exact configuration while still
created. Do not start a container with broader/mismatched settings.

Require networknone, private PID/IPC/cgroup/UTS defaults, no host user namespace,
nonroot current UID/GID, cap-dropALL, no-new-privileges, read-only image filesystem,
no port bindings/devices/extra mounts, bounded memory/CPU/PIDs and no restart or
auto-removal. Only exact native/HMP source directories, Python prefix, environment
and entry file are read-only mounts; the one scenario root is writable. Standard
private container pseudo-filesystems remain present; no claim that bind mounts
are the only kernel-created mounts. No Docker socket, host home or credentials
are mounted into the container. Child environment is a fixed synthetic allowlist.
The native entry separately observes actual interfaces and requires onlylo.

Record start intent, start the verified ID once, then read-only inspect that SAME
ID/configuration to terminal. Docker CLI exit is not container settlement.
The reviewed existing CLI helper pre-owns the actual process object before
construction, including lost constructor return. Every CLI child is joined,
including its12-second observation timeout; late settlement refuses acceptance.
Only that generic process helper is used; its native C fixture never runs. There
is no kill/stop or restart. A900-second scenario deadline records failure, then continues
observing the same container until terminal. Inspection failures, validation or receipt-write errors retain an outer
reconciliation path for the same full ID or pre-owned unique name. It continues
read-only observation through transient failures, never restarting/advancing. A
created object is recorded inert only if no start was ever attempted; an
ambiguous create/start remains pending. Diagnostic write errors do not abandon
this ownership. There is no actor release or replay claim. External
runner cancellation may leave unknown cleanup; it is never a pass.

Bounded local Docker logs are private synthetic diagnostics and are fetched only
for the known terminal container. Raw inspect, logs and native report files stay
private; publish only a fixed curated outcome. The entry may include exception
text/traceback containing synthetic sensitive state. Do not upload raw artifacts
or stream them to public CI logs. Terminal containers are retained, not deleted
or reused by this controller. A failed scenario prevents further scenarios.
