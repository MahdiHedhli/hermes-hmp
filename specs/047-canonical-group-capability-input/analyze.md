# Consistency analysis

GC1/GC4 establish input/type/resource refusal. GC2 prevents privilege manufacture;
GC3 preserves the minimum-supported-version policy without equating a new native
protocol number to a qualified implementation. GC5 prevents discovery leakage.
GC6 keeps the closed plugin/outbound surface and live authority unchanged. GC7
keeps a malformed read from becoming success. All have acceptance scenarios and
negative tests in the task list. No production route or wire contract changes.

This slice deliberately cannot answer which device may read/control which room.
That requires a separately reviewed grant/entitlement and canonical transport
contract. Existing pairing, Bot Chat, Jobs/Models and approval-owner privileges
will not be reused as group/admin rights. New source is not full GR1 completion.

Independent contract review accepted with one correction: exact dict type alone
is not a guarantee against foreign-key equality callbacks. Keys now undergo a
bounded shallow type/length pass before lookups; ignored values remain untouched.
Method queries also require exact built-in Strings before membership checks.
