# Signed pre-GO CANCEL native adoption — November 6, 2026

This source-only component connects the original authenticated first-control read
to existing native CANCEL grammar, cancellation budget, receipt notification and
owned local controller park/stop. It does not integrate ordinary service receipt
consumers, signed GO, after-GO or cleanup-time control reads, resources/READY,
production startup, native output publication or physical/release qualification.

`BrokerCancellationOwner.retain_credential_cancel(queued_owner)` derives only the
original prepared controller, signed cursor and adopted connection. The actual
original controller Task completes and revalidates its retained signed read;
`CredentialCancelAdoption` accepts only CANCEL sequence1 before the original
signed work end. A caller-created frame/consistency object cannot be supplied.
The complete read seals phase, end, original bytes, buffer and consumed offsets.
Every later native callback is followed by callback-free original-completion and
primitive metadata fences before comparison, parsing or lifecycle effects.

Before the first native mutation, the one-attempt intent is consumed. Local cause
freezes the existing budget, native grammar observes CANCEL, and the validated
remote window is inherited without lengthening the earlier end. Existing native
`_CancelReceipt`, original allocation, original Future and timeout are retained
before notification. The exact original Task then parks. Supported local abort
and stop validation can complete this park after role keys retire; retirement
continues to refuse new remote authentication/effects. No task completion, receipt
or local stop proves registry/resource/native debt release.

The existing `cancel_receipt()` and service `_v2_control` still reject credential
owners through their ordinary work guards. Tests observe the original internal
Future and separately validate actual owned local stop. A dedicated authenticated
service receipt validator remains required; relaxing the generic work guard is
not an acceptable substitute. A notification Future alone is insufficient: the
post-notification key-retirement causal has a completed Future but a failed owner
and retained uncertainty. No consumer may certify that as usable adoption.

Independent source/test review accepted this bounded component without execution.
Root affected regression passed **1,151 tests, one skipped**, in 32.13 seconds;
configured repository-wide lint passed. Final focused module passed **55 cases**
in 5.31 seconds, including the subsequently added post-notification retirement
causal. Success cases cover original CANCEL receipt/window minimum and actual
local stop, including keys retired while parked. Refusal cases cover GO, future
window, bad signature, retirement after native inheritance, and late foreign
phase/end values with zero comparison callbacks/local causes/budget/grammar/
notice effects. Prior cursor causals remain included. Fixtures use synthetic
keys/peer/clock policy with real disposable sockets/tasks/native registry objects;
there is no live host, mobile build, permission, provider or key installation.
